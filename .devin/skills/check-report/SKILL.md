# レポートのプライバシーチェック

このrepoの `docs/`・`README.md`・`AGENTS.md`・`hooks/`・`bin/`・`tools/` を
公開前提でスキャンし、残すべきでない情報を検出 → 削除または一般化する。

## チェック観点

### 即削除（機密）

- APIキー・トークン・パスワード・`.env` の中身・接続文字列
- 秘密鍵・認証情報らしき文字列

### 削除 or 一般化（個人情報・非公開情報）

- 本名・メールアドレス・電話番号・SNSアカウント
- `/Users/<name>/`、`/home/<name>/` などユーザー名を含む絶対パス → `~/` に一般化
- ホスト名・IP・非公開ドメイン・SSH接続先 → 「別マシン」「リモートホスト」等に
- 非公開repo名・プロジェクト名・顧客/取引先名・未公開の仕様や業務内容
  → 分析価値を残す形で一般化（例: 固有名 → 「あるrepo」「あるbot」）
- transcripts からのユーザー発言の生引用 — 愚痴・私的な話・社内情報を含みうるため
  原則として要約に置き換える。セッションslug（`enchanting-bead` 等）は
  不透明なIDなので残してよい

### グレーゾーン（判断してユーザーに確認）

- マシン名・環境の固有情報 — 再現性の文脈で必要なら残す判断もあり
- 分析セッションでやっていた作業の内容そのもの

## 手順

1. 対象を特定（引数で指定がなければrepo全体）
2. パターンスキャン:
   ```
   grep: /Users/|/home/|@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|\b[0-9]{1,3}(\.[0-9]{1,3}){3}\b|ssh |api[_-]?key|token|secret|password|Bearer
   ```
3. 全文を意味レベルで読み、パターンに引っかからない
   「公開されたら困る/恥ずかしい」記述を拾う（具体的な作業内容・人名・内輪の話）
4. 結果を分類して処理:
   - 機密 → 即削除
   - 個人情報・非公開情報 → 一般化して置換（事実関係・分析価値を損なわない範囲で）
   - グレーゾーン → 削除案を列挙し、ユーザーに確認してから処理
5. 修正後に同じスキャンを再実行し、残留がないことを確認する

## 注意

- 分析レポートの価値は具体性にある。「全部ぼかす」ではなく
  「誰の・何の情報か分からない形にする」のが目標
- 削除で文脈が壊れる場合は、一般化した表現への置き換えを優先する
