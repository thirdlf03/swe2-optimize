# バックグラウンドサブエージェントのユーザー発言キャンセル

親エージェントがバックグラウンドで `run_subagent` を走らせている間に
**ユーザーが通常の発言をすると、実行中のサブエージェントが
`Canceled by user` で終了する**事象を観測。成果物は worktree に
残ったため復旧可能だったが、約27分の実行が中断された。

## 観測データ

| 時刻(UTC) | イベント |
|---|---|
| 09:25:43 | 親が `run_subagent`（is_background）で実装サブエージェント `ff5f942c` 起動 |
| 09:26:27 | 親はステータス報告後アイドル（完了通知待ち） |
| 09:52:26 | ユーザー発言（追加タスクの依頼） |
| 09:52:30 | ユーザー発言（稼働状況の確認） |
| 09:53:01 | `read_subagent(ff5f942c)` → **"Subagent ff5f942c exited with an error: Canceled by user"** |

- ユーザーは単に状況確認のつもりの発言だったが、実行中サブエージェントが
  死亡。未コミットの作業途中ファイル（`M`/`??` 4件）は worktree 上に残存
- 親は `git status`/`git diff` で途中状態を確認し、
  `run_subagent(resume=ff5f942c)` で再開→完了
- 以降このセッションでは、ユーザー発言と重ならないタイミングで
  実装/レビューのサブエージェントを並走させて全タスク完走

## 根本原因（構造）

- **「親がアイドル + バックグラウンド実行中」の状態で新しいユーザー
  発言が入ると、子まで巻き込んでキャンセルされる**（CLI バージョン
  3000.10.21 で観測）
- ユーザーの視点では状況確認は割り込みでなく雑談だが、
  ハーネス上は新ターン開始＝実行中コンテキストの中断として処理される
- 救いになったのは**サブエージェントが git worktree で作業していた**
  こと。プロセスが死んでも未コミット WIP がディスクに残り、
  `resume` で続行できた

### バージョン間の差異（未確定）

現行ドキュメント（3000.10.27 同梱）には「中断はサブエージェントを
park させ、次のメッセージで resume する」とある。観測した 10.21 での
`Canceled by user` は (a) 当時の仕様が cancel だった、
(b) 親アイドル中の新規発言は interrupt ではなく cancel 経路を通る、
のどちらか。**10.27 で再現確認していないため未確定**。

## 悪いパターン / 良いパターン

| | 形 | 結果 |
|---|---|---|
| ❌ bg サブエージェント稼働中にユーザーが状況確認の発言 | 確認発言のみで子プロセス死亡 | 27分の実行中断。再開は手動 resume |
| ✅ サブエージェントの作業場所を git worktree に隔離 | プロセス死亡しても WIP が残る | `resume` で継続、ロスなし |
| ✅ キャンセル検出時に WIP 確認→resume 再開 | `git status`/`git diff` で中途確認後 `run_subagent(resume=…)` | 最終的に全タスク完走 |

## 対策

機械的に防ぐ方法は現状ない（ユーザーの発言自体をフックで止めることは
できない）。緩和:

1. **サブエージェントの作業は必ず worktree/別ディレクトリで**
   — 今回これが唯一かつ十分な保険だった。dispatch プロンプトの
   定型に含める価値がある（本repoでは観測された dispatch が
   既にこの形を取っていた）
2. **長時間 bg サブエージェント起動時は、ユーザーへ一言添える**
   — 「実行中に発言すると子タスクが中断する可能性がある」旨。
   ユーザーの状況確認は善意のものであり、
   発言コストが高いことを知らせる
3. **キャンセル検出時の定型**: `read_subagent` が `Canceled by user`
   を返したら (a) WIP を `git status` で確認 (b) `resume` で再開
   (c) ユーザーに中断が起きた旨を報告 — の流れで回復可能

## 残課題・限界

- 10.27 で「pause + resume」に改善済みか未検証。次回サブエージェント
  運用時に、ユーザー発言を挟んで挙動を確認する余地あり
- 対策2（ユーザーへの予告）は自然言語の依頼であり強制力なし
- フック化の余地: `run_subagent` の PreToolUse フックで
  「is_background かつ worktree 指定なし」なら警告を返す、
  という間接ガードは実装可能だが、観測1件だけでは
  コスト対効果が読めないため未実装
