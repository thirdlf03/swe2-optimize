# 確信度の高い誤初回回答（premature confident answers）

エージェントが**証拠の網羅確認をする前に、もっともらしい結論を確定的な
言い方で返す**パターン。ユーザーが品質ゲートの役割を担わされ、
1回の突っ込みごとに1往復＋やり直しのコストが発生する。
最悪の変種は「質問・文章への捏造混入」（ハルシネーションの提示）。

## 根本原因

### 1. 「最初に辿り着いた整合的な答え」で止まる

再調査で正解に辿り着くのは、**最初の探索で見落とした資料を
ユーザーの疑問がトリガーとなって開き直す**からであることが多い。
pushy-oregano では見積シートの行だけ見て結論し、別ファイル
（HTML 画面フロー）の注記を見ていなかった。balsam-fire は
「未解決スレッド」だけ見て「人間のコメント」を見ていなかった。
**探索の打ち切り条件が「答えが見つかった」であり
「候補を全部見た」ではない。**

### 2. 質問生成が「根拠のある開いた問い」ではなく「もっともらしい具体」を生む

cheddar-sprite の捏造質問は、物語として自然な具体を
前提込みで質問に埋め込んだもの。**ユーザーが曖昧に肯定すれば
捏造が記録に定着する**構造的に危険な失敗であり、実際にユーザーが
2度否定して初めて発覚した。

> **構造的問題**: 生成物が一度プロジェクト内ドキュメントに書かれると、
> それが次回以降の「根拠」として参照される（自己増殖）。
> cheddar-sprite でも企画書に混入した語句が質問の種になっていた。

### 3. 「捏造禁止」ルールが既に存在しても破られた

対象プロジェクトには「質問に捏造を埋め込まない」が**最重要ルールとして
既に存在した**にもかかわらず破られた。自然言語ルールが強制力を
持たないことの、本パターンにおける直接証拠。

## 悪いパターン / 良いパターン

| | 形 | 結果 |
|---|---|---|
| ❌ 部分資料で結論 → 断定的に回答 | 集計シートの1行のみで「対象外」と判断 | 全 revert + 再編集の往復 |
| ❌ 質問に存在確認していない具体を埋め込む | 存在しない出来事4件 | ユーザーが事実確認役を負担。曖昧応答なら記録汚染 |
| ❌ 「A だけチェックした」のに「全部見た」口調で報告 | AIスレッドのみ走査 → 「要対応はこれだけ」と報告 | 人間コメント3件の検出漏れ |
| ✅ 断言の前に一次資料へ戻る | ブランド名指摘をコミット履歴で確認してから修正実行（global-writer） | 裁定違反の確定→正しい修正 |
| ✅ 「分からない/未確認」を明示 | devbox/Nix の権限問題を「ここまで、残りはユーザー操作が必要」と切り分け（butter-walker） | 無駄な試行を回避 |

## 対策

**機械的に完全には防げない**（事実性はコマンド文字列から判定できない）。
実装した強制策はなく、本docは観測の備忘として残す。緩和策:

1. **回答前の網羅チェックを定型化する**: 「要対応一覧」「含まれる/含まれない」
   系の回答では、列挙した項目それぞれについて出典ファイルを示す習慣を
   ルールに書く価値はある（効果は限定的と実測済みだが、コストは小さい）。
2. **事実前提の質問はコーパス参照つきで**: 質問生成系ドメインでは
   「質問内の固有事実はすべて出典ファイル:行を添付する」運用。
   出典が無い問いは「〜はありましたか？」の開いた形に落とす。
3. **revert 前提で大編集しない**: pushy-oregano 型（判断→広範囲編集）では
   「削除前に根拠資料の相互参照を grep で洗う」一手間が revert コストを防ぐ。
4. **ユーザー側の運用**: 「本当に？」と聞き直せば訂正される実績があるため、
   重要な断言には一度突っ込むのが現実的な最終防衛線になっている
   （= 現状はユーザーが品質ゲート）。

## 残課題・限界

- フック等の機械的防止は未実装。「出力の真実性」を判定するプリミティブが
  exec レベルに存在しない。根拠ファイル列挙を強制する仕組み（例:
  回答フォーマットへの出典必須化）はプロンプト層の話であり、
  強制力を持たせる術が現状ない。
- 5 セッション全て別ドメイン（PR管理・仕様書・料金調査・質問生成）
  での観測であり、ドメイン固有でないことは確認できたが、
  「どの程度の確信で口にするか」の閾値を外部から測る手段は無い。
